# Эстафета

Веб-система сохранения и передачи корпоративных знаний (RAG) для одной организации.

Клиент: **React + TypeScript (Vite)**. Решения этапа 0: [docs/etap-0.md](docs/etap-0.md).

## Запуск

Нужны Docker, Docker Compose и (для локальной разработки UI) Node.js 22. Секреты не хранятся в git.

```powershell
copy .env.example .env
docker compose up --build
```

Откройте [локальный интерфейс](http://localhost:8080). Адрес должен совпадать
с `AUTH_PUBLIC_ORIGIN`.

API напрямую (после запуска backend): http://127.0.0.1:8000/api/health — порт 8000 снаружи не публикуется, запросы идут через Nginx на 8080.

Миграции выполняет сервис `migrate` ролью `estafeta_owner`. Приложение подключается ролью `estafeta_app`.
Если база уже работала на этапе 3, создайте отдельную роль администратора
перед обновлением. [Обновление существующей БД](docs/etap-4.md#обновление-базы-с-этапа-3)

### Первый вход

Укажите свою корпоративную почту в `BOOTSTRAP_ADMIN_EMAIL` и задайте уникальный
`APP_SECRET_KEY` в `.env`. Выполните команду после запуска стека.

```powershell
docker compose run --rm migrate python -m estafeta.auth.bootstrap
```

Откройте ссылку из вывода команды, задайте пароль и войдите. При первом входе
администратор настраивает TOTP в приложении-аутентификаторе. После настройки
он может выдавать ссылки на 72 часа для существующих сотрудников. Подробнее
о сессиях, восстановлении и SMTP см. в [документации этапа 3](docs/etap-3.md).

Аудитор ИБ может читать журнал через `GET /api/audit/events`.
[Фильтры и навигация по журналу](docs/etap-5.md#чтение)

Сотрудник может добавить заметку или файл через «Учётная запись → Добавить материал».
[Поддерживаемые форматы и политика очистки](docs/etap-6.md)

В разделе «Материалы и записи» можно отправить черновик на проверку,
открыть публикации отдела и скопировать запись к себе. Администратор
управляет обязательностью проверки в «Настройках публикации».
[Публикация и копирование](docs/etap-7.md)

Кнопка «Собрать базу» запускает индексацию и извлечение записей в фоне.
Для сборки настройте OpenAI-совместимый endpoint и доступ воркера к BGE-M3.
На существующей БД сначала создайте ограниченную роль воркера.
[Настройка фоновой сборки](docs/etap-8.md)

После сборки откройте «Поиск и вопросы по базе». Выберите область и нажмите
«Найти» или «Спросить ИИ». После обновления с этапа 8 запустите сборку повторно,
чтобы старые фрагменты вошли в векторную выдачу.
[Поиск, история и настройка моделей](docs/etap-9.md)

HR и руководитель создают планы увольнения и перевода в разделе «Эстафеты».
В форме задаются последний рабочий день и точное время блокировки.
[Эстафеты и политика хранения](docs/etap-10.md)

### Локальная разработка без контейнера API

Поднимите только БД: `docker compose up db`. Затем:

```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
copy ..\.env.example .env
# DATABASE_* в .env должны указывать на localhost
# AUTH_PUBLIC_ORIGIN для Vite — http://localhost:5173
alembic upgrade head
uvicorn estafeta.main:app --reload --port 8000
```

```powershell
cd frontend
npm ci
npm run dev
```

Vite проксирует `/api` на `http://127.0.0.1:8000`.

### Тесты

```powershell
cd backend
ruff check estafeta tests alembic
pytest -q
```

Для интеграционных тестов нужен отдельный тестовый PostgreSQL 16 с pgvector.
Задайте `DATABASE_URL`, `DATABASE_OWNER_URL` и `DATABASE_ADMIN_URL`
для ролей тестовой БД. Команды выполняются в каталоге `backend/`.

```powershell
alembic upgrade head
alembic check
$env:RUN_DB_TESTS = "1"
pytest -q
```

GitHub Actions выполняет эти проверки на отдельной тестовой БД.

Playwright (стека должен быть на 8080):

```powershell
cd frontend
$env:E2E="1"
npm run test:e2e
```

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `APP_SECRET_KEY` | секрет приложения для CSRF и шифрования TOTP (≥ 32 символов) |
| `DATABASE_URL` | PostgreSQL, роль приложения `estafeta_app` |
| `DATABASE_ADMIN_URL` | отдельное подключение `estafeta_admin` для административных действий API |
| `DATABASE_OWNER_URL` | PostgreSQL, роль владельца таблиц (только миграции) |
| `POSTGRES_PASSWORD` | пароль суперпользователя контейнера БД |
| `ESTAFETA_OWNER_PASSWORD` / `ESTAFETA_APP_PASSWORD` | пароли ролей |
| `ESTAFETA_ADMIN_PASSWORD` | пароль ограниченной роли `estafeta_admin` в Compose |
| `ESTAFETA_WORKER_PASSWORD` | пароль роли `estafeta_worker` в Compose |
| `DATABASE_WORKER_URL` | отдельное подключение воркера при локальном запуске |
| `CORS_ORIGINS` | список origin через запятую (для Vite); в Compose за Nginx пустой |
| `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY` | OpenAI-совместимый LLM (этапы RAG) |
| `EMBEDDING_MODEL` / `EMBEDDING_REVISION` | имя или локальный путь BGE-M3 и ревизия модели |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | размер и перекрытие фрагментов, по умолчанию 900 и 160 |
| `LLM_TIMEOUT_SECONDS` | таймаут HTTP-клиента LLM, по умолчанию 35 секунд |
| `RAG_TOP_K` | максимум фрагментов в выдаче и запросе к модели, по умолчанию 8 |
| `HANDOFF_RETENTION` | хранение личного пространства после разбора, `archive` по умолчанию или `delete` |
| `SESSION_IDLE_MINUTES` / `SESSION_MAX_HOURS` | 30 / 12 по умолчанию |
| `AUTH_PUBLIC_ORIGIN` | точный origin интерфейса, применяется к POST-запросам и ссылкам |
| `AUTH_TRUST_PROXY_IP` | доверие к `X-Real-IP` от Nginx, включено в Compose |
| `BOOTSTRAP_ADMIN_EMAIL` | первый администратор (этап 3) |
| `SMTP_*` | опциональная почта приглашений |
| `REDACTION_POLICY_FILE` | путь на хосте к JSON с политикой очистки для Compose |
| `REDACTION_POLICY_PATH` | путь к JSON, доступному процессу API при локальном запуске |
| `TZ` | `Europe/Moscow` |

Полный шаблон: `.env.example`.

Compose публикует HTTP на loopback для разработки. TLS Nginx и сертификаты
предусмотрены на этапе 12. Для развёртывания раньше этапа 12 используйте
существующий HTTPS-прокси организации с настроенным `AUTH_PUBLIC_ORIGIN`.
Хостинг и бэкапы в проде — на территории РФ.
