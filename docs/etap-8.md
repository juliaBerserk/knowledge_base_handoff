# Этап 8 — фоновая сборка

Сотрудник запускает сборку кнопкой «Собрать базу». В неё входят его собственные
доступные материалы со статусом «черновик» или «опубликовано». Собранные фрагменты
публикаций доступны по тем же правам, что и материал. Записи, извлечённые моделью,
появляются в личных черновиках автора и проходят обычную публикацию.

Миграция `0008_indexing` добавляет очередь `knowledge.jobs`, фрагменты
`knowledge.chunks` и поля категории, уверенности и ссылки на фрагмент у записи.
Для активных фрагментов создаются GIN по `tsvector` с конфигурацией
`russian` и HNSW по вектору BGE-M3 размерности 1024. Поисковые запросы
должны явно фильтровать `active`.

Воркер забирает задачу через `FOR UPDATE SKIP LOCKED`, продлевает аренду при
обработке документа и заново проверяет права при смене этапа. После истечения
аренды задачу можно подобрать повторно. На пользователя действует ограничение
в одну активную сборку. Изменения публикуются транзакцией для каждого материала.
Повторная сборка пропускает материалы с тем же хэшем текста и той же конфигурацией.
Изменение текста или версии конфигурации запускает пересборку материала.

Запись содержит категорию, уверенность модели и её дословную цитату. API
извлечения проверяет цитату по фрагменту. Ручные правки и уже опубликованные
записи сохраняются при пересборке. Устаревший автоматически созданный черновик
без ручных правок архивируется. Историческая цитата под правленой записью
доступна её автору, пока он сохраняет право чтения материала.

## Запуск

Для новой базы `docker compose up --build` создаёт роль воркера и применяет
миграцию. На существующей БД добавьте `ESTAFETA_WORKER_PASSWORD` в `.env` и
создайте роль кластерным администратором перед миграцией:

```sql
CREATE ROLE estafeta_worker LOGIN;
\password estafeta_worker
GRANT CONNECT ON DATABASE estafeta TO estafeta_worker;
GRANT estafeta_app TO estafeta_worker WITH INHERIT TRUE, SET FALSE;
```

Подставьте имя своей БД и введите тот же пароль, что указан в `.env`.
При запуске вне Compose установите зависимости с `pip install -e '.[worker]'`,
задайте `DATABASE_WORKER_URL`, затем запустите `python -m estafeta.workers.runner`.

Задайте `LLM_BASE_URL`, `LLM_MODEL` и при необходимости `LLM_API_KEY`
для доступного воркеру OpenAI-совместимого сервера. Для Docker адрес
`host.docker.internal` указывает на хост. При прямом запуске на хосте укажите
его локальный адрес явно. Используйте сервер, на который организация разрешает
передавать очищенный корпоративный текст. Данные должны оставаться на территории РФ.

Воркер загружает BGE-M3 при первой сборке. Compose сохраняет веса в томе
`model_cache`. Для воспроизводимого запуска задайте `EMBEDDING_REVISION` или
укажите путь к предварительно установленной модели в `EMBEDDING_MODEL`.

## API

- `POST /api/build` ставит сборку в очередь. Требуется CSRF-токен.
- `GET /api/build` возвращает последнюю задачу сотрудника, `job_id` выбирает
  конкретную. Прогресс включает количество собранных, пропущенных и ошибочных
  материалов. Сообщения провайдера и текст в ошибки не попадают.
- `GET /api/build/sources/{id}` открывает фрагмент после проверки доступа.
- `POST /api/build/records/{id}/edit` очищает и сохраняет правку личного
  черновика, помечая его как отредактированный вручную.
