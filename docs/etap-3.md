# Этап 3 — аутентификация и учётные записи

## Реализовано

- Локальный auth-provider, Argon2id и установка пароля только по одноразовой
  ссылке-приглашению на 72 часа. В БД сохраняются только хэши токенов.
- Минимум 12 символов для пароля и проверка по локально монтируемому списку
  частых паролей. Отсутствующий или пустой файл запрещает установку пароля.
- HttpOnly session cookie, CSRF-cookie и проверка CSRF-заголовка; idle- и
  абсолютный срок сессии настраиваются. Для входа действуют IP rate limit и
  блокировка учётной записи после пяти неверных паролей.
- TOTP обязателен для администраторов и руководителей; повторное использование
  кода в одном временном шаге запрещено. Потерянный доступ восстанавливает
  администратор новой одноразовой ссылкой, которая отзывает активные сессии.
- Создание и CSV-импорт учёток администратором, приглашения и восстановление,
  разблокировка, выход и просмотр текущей сессии.
- PostgreSQL RLS для учётных данных и сессий; `estafeta_app` видит только
  учётные данные текущей учётки. Разблокировка выполняется узкой DB-функцией,
  которая проверяет роль администратора. Пароли не доступны администратору
  через API или роль приложения в БД.
- Bootstrap первого администратора командой:

  ```powershell
  docker compose run --rm backend python -m estafeta.cli bootstrap-admin --name "ФИО администратора"
  ```

  При пустой базе команда создаёт приглашение и выводит ссылку в консоль.
  Передайте ссылку лично, если SMTP не настроен. Команду нельзя повторно
  использовать после создания администратора.

## API

- `POST /api/auth/invitations/accept` — задать пароль по приглашению.
- `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`.
- `POST /api/auth/totp/setup`, `POST /api/auth/totp/verify`.
- `POST /api/admin/users`, `POST /api/admin/users/import-csv`.
- `POST /api/admin/users/{user_id}/recovery-invitation`,
  `POST /api/admin/users/{user_id}/unlock`.

Административные маршруты требуют активной сессии администратора и CSRF-защиту.
В CSV обязательны `full_name,email,department,position,role`, максимум 500 строк
и 1 МБ. Ссылка приглашения возвращается администратору и отправляется письмом,
если настроен SMTP.

## Настройка

- `COMMON_PASSWORDS_HOST_FILE` — путь на хосте, монтируемый только для чтения;
  `COMMON_PASSWORDS_FILE` — путь внутри контейнера. Маленький файл в репозитории
  является примером разработки, а не утверждённым production-списком.
- `AUTH_COOKIE_SECURE=true` в production за HTTPS; для локальной разработки на
  HTTP в `.env.example` задано `false`.
- Для почты задаются `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, а при
  аутентификации также `SMTP_USER` и `SMTP_PASSWORD`. Используется STARTTLS.
- `PUBLIC_BASE_URL` должен соответствовать внешнему адресу системы, чтобы ссылки
  приглашений в API и письмах вели на правильный хост.

## Проверки и ограничения

Локально: `ruff check estafeta tests alembic` и `pytest -q` — **80 passed,
3 skipped**; веточное покрытие `estafeta.domain.access` — **100%**. Пропущены
PostgreSQL-интеграционные тесты, потому что локальная PostgreSQL/Docker-среда
недоступна; CI запускает их на PostgreSQL и применяет Alembic-миграции отдельной
ролью владельца. Подтвердите выполнение интеграционного задания в CI перед
внедрением.

OIDC/LDAP-провайдеры, интерфейс управления, ротация/ревокация приглашений
пользовательским интерфейсом и управление устройствами TOTP ещё не реализованы.
