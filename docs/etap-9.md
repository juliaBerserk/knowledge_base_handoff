# Этап 9 — поиск и ответы по базе

В интерфейсе «Поиск и вопросы по базе» доступны области «Моё», «Моя должность»
и «Мой отдел». Права применяются в обеих выборках PostgreSQL до ранжирования.
Выдачи Russian FTS и HNSW объединяются через RRF. Результат ограничен
`RAG_TOP_K` (8 по умолчанию). При недоступности эмбеддера поиск использует FTS.

Модель получает очищенный вопрос и только фрагменты из выбранной области.
Каждый вопрос обрабатывается по свежей выдаче. История служит пользователю
для просмотра прошлых ответов. Документный текст помещается в отдельный блок
данных. В SSE выдаются лишь дословные цитаты, сверенные с фрагментами. Ссылки
открывают источник с повторной проверкой прав. При отсутствии подтверждённых
цитат ответ сообщает «в базе нет информации».

Перед выдачей очередной цитаты и при сохранении ответа доступ перепроверяется.
При чтении истории ответ скрывается, если его источники больше недоступны.
Рейтинг и комментарий хранятся с ответом. В журнал аудита попадает UUID чата,
UUID сотрудника и факт вопроса. Вопрос и ответ остаются в закрытой истории.

## Запуск

После `docker compose up --build` применяется миграция `0009_rag`. API и воркер
используют общий кэш весов BGE-M3. Настройте одинаковые `EMBEDDING_MODEL` и
`EMBEDDING_REVISION` для обоих процессов. Для запуска API вне Compose
установите `pip install -e '.[worker]'`.

Укажите доступный воркеру и API OpenAI-совместимый endpoint с поддержкой
стриминга. Служебный процесс обращается к нему через `LLM_BASE_URL`,
`LLM_MODEL` и `LLM_API_KEY`. Используйте согласованный организацией endpoint
на территории РФ.

После обновления с этапа 8 повторите сборку. Фрагменты, созданные до
обновления, участвуют в полнотекстовом поиске. Пересборка указывает модель
эмбеддингов, после чего фрагменты участвуют и в векторном поиске.

## API

- `POST /api/search` принимает `question` и `scope`.
- `POST /api/chat/ask` дополнительно принимает необязательный `chat_id`
  и возвращает SSE-события `started`, `citation`, `done` или `error`.
- `GET /api/chat` и `GET /api/chat/{id}` возвращают личные чаты и ответы.
  `before` задаёт курсор предыдущей страницы.
- `POST /api/chat/{id}/delete` удаляет чат, ответы и оценки.
- `POST /api/chat/turns/{id}/feedback` принимает `rating` (−1 или 1) и комментарий.

POST-запросы требуют JSON и CSRF-токен. Вопрос ограничен 1000 символов.
Ограничения на сотрудника составляют 30 поисков и 8 вопросов за минутное
окно. Вместе с ответом сохраняются версия промпта и идентификатор модели.
