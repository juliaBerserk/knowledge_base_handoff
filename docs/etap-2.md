# Этап 2 — оргмодель

Ревизия Alembic `0002_org_model` добавляет схему `knowledge`.

- `departments`, `positions`, `employees` и `position_assignments` хранят оргструктуру,
  роли и историю назначений. У сотрудника может быть одно незакрытое назначение.
  Должность может оставаться вакантной. Корпоративная почта необязательна. База
  требует, чтобы указанное значение было уникальным, в нижнем регистре и без
  пробелов по краям.
- `spaces` хранит по одному пространству на владельца соответствующего типа.
  Публикации связаны с должностью через её пространство. Авторство связано с
  сотрудником и сохраняется после закрытия назначения.
- `materials` и `records` хранят метаданные. Черновики и записи на проверке
  связаны с личным пространством, опубликованное — с пространством должности.
  Архивные элементы сохраняют связь со своим пространством. Пространство отдела
  служит областью чтения опубликованного по должностям отдела, без отдельного
  хранения материалов и записей.

Роль приложения в Compose получает доступ к схеме только после явной выдачи
привилегий. URL владельца предназначен для сервиса миграций. Публичный
HTTP-эндпоинт этапа — `GET /api/health`.

Команда `docker compose up --build` запускает миграции перед API. Для отдельного
тестового PostgreSQL инструкции приведены в [README](../README.md). Откат до
`0001_baseline` удаляет схему `knowledge` вместе с её данными.
