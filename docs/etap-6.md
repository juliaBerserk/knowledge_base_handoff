# Этап 6 — приём и очистка материалов

Сотрудник или руководитель отдела открывает «Учётная запись → Добавить материал»,
выбирает файл или вводит заметку, проверяет предпросмотр и сохраняет результат
как личный черновик. Максимальный размер файла — 20 МБ. Поддерживаются TXT
и Markdown в UTF-8, DOCX без макросов и PDF с текстовым слоем. Предел извлечённого
текста составляет 150 000 символов. PDF больше 300 страниц отклоняется.
Для сканов нужен внешний OCR.

API передаёт двоичное тело в памяти. Nginx отключает буферизацию тела запроса
на маршрутах материалов. Для DOCX проверяются размеры и имена элементов архива.
Разбор документов ограничен по времени. В Linux процесс разбора также получает
лимиты CPU и памяти. Исходник не сохраняется на сервере и не передаётся модели.

Очистка сочетает регулярные выражения, проверку Луна и Natasha. Извлечённые
ФИО сверяются с рабочим справочником с учётом форм имени. Должности и
корпоративные адреса из справочника сохраняются, если не находятся внутри секрета.
Значения заменяются типизированными метками. Автор может дополнительно скрыть
выделенный фрагмент и отметить подходящий контакт как рабочий. Контакт, который
пересекается с обязательным скрытием, нельзя восстановить этой отметкой.
Автоматическая очистка не гарантирует обнаружение всех данных.

## Настройка правил

Скопируйте шаблон `deploy/redaction/policy.json` в отдельный `redaction.local.json`
и укажите `REDACTION_POLICY_FILE=./redaction.local.json` в `.env`. API считывает
файл для каждого предпросмотра или сохранения.

- `internal_domains` добавляет домены, для которых рабочими признаются только
  адреса из справочника.
- `secret_labels` добавляет имена параметров, значения которых нужно скрывать.
- `confidential_terms` добавляет слова или выражения для буквального поиска.
- `additional_rules` принимает объекты с полем `pattern` и опциональным
  `kind`. По умолчанию тип метки — `confidential`. Если в шаблоне есть
  именованная группа `value`, скрывается только она.

Встроенные правила действуют при любой конфигурации. Некорректный
файл политики или превышение лимита времени регулярного выражения
останавливает сохранение.

## API и хранение

- `POST /api/materials/preview` выдаёт очищенный текст, координаты меток
  и подтверждение предпросмотра на 15 минут.
- `POST /api/materials` повторно получает исходник и проверяет подтверждение
  для того же сотрудника, файла и набора отметок. Повтор сохранения с тем же
  подтверждением возвращает тот же идентификатор.
- `GET /api/materials/{id}` возвращает материал после проверки RLS и прав.

Оба POST-запроса используют `application/octet-stream`, заголовок формата
`X-Material-Format` и CSRF-токен. `X-Material-Choices` передаёт JSON с массивами
`work` и `hide`. Сохранение дополнительно требует `X-Material-Proof`.

Миграция `0006_materials` добавляет очищенный текст и формат к материалу.
Транзакция сохраняет черновик и события аудита с типами и количеством скрытого.
Исходные значения и имя файла в аудит не попадают. Применение миграции —
`docker compose up --build`.

Сквозной тест формы запускается командой `npm run test:e2e -- e2e/materials.spec.ts`
из каталога `frontend`. Перед запуском задайте `E2E_MATERIAL_LOGIN` и
`E2E_MATERIAL_PASSWORD` для сотрудника отдельной тестовой БД.
