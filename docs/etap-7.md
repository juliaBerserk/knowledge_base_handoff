# Этап 7 — фоновая сборка и индексация

## Реализовано

- Очередь `build_jobs` с атомарным захватом задания через PostgreSQL
  `FOR UPDATE SKIP LOCKED`; зависшие задания повторяются ограниченное число раз.
- Отдельный Compose-сервис `worker`; ошибка обработки одного материала не
  останавливает остальные.
- Инкрементальная обработка актуальных версий материалов, чанки с перекрытием,
  векторы BGE-M3, полнотекстовый `russian` GIN-индекс и HNSW pgvector.
- Извлечение десяти категорий знаний через OpenAI-совместимый клиент группами
  фрагментов; каждый результат связывается с фрагментом-источником и оценкой
  уверенности. Результаты очищаются до сохранения.
- Сохранение ручных правок при повторной сборке. Старые автоматически
  извлечённые записи без ручных правок и чанки помечаются неактуальными;
  пользовательские правки остаются текущими.
- RLS для заданий, чанков и ссылок источников; доступ к заданию ограничен его
  автором. Worker получает задание через ограниченную функцию захвата.

## API и запуск

- `POST /api/build-jobs` — поставить сборку в очередь.
- `GET /api/build-jobs` — последние задания текущего пользователя.
- `GET /api/build-jobs/{id}` — состояние и прогресс своего задания.
- В Compose задания обрабатывает сервис `worker`; вручную его запускать не
  требуется.

Для разработки скопируйте `.env.example` в `.env` и задайте адрес LLM,
доступный из контейнера. BGE-M3 загружается при первой сборке. Для production
без внешних загрузок заранее разместите модель внутри инфраструктуры и задайте
путь к локальным весам через `EMBEDDING_MODEL`.

Проверки: `ruff check estafeta tests alembic` и `pytest -q` из `backend`.
PostgreSQL-интеграционные тесты включаются через `RUN_DB_TESTS=1`.

## Граница этапа

Этап не реализует пользовательский экран запуска сборки, гибридный поиск,
ответы RAG и управление эстафетой; это последующие этапы. До завершения этапа
проверьте применение и откат Alembic-миграции на PostgreSQL 16 с pgvector.
