# Этап 4 — права и RLS

Модуль `core.permissions` проверяет чтение, правку черновиков, публикацию
и копирование. При публикации вызывающий код дополнительно подтверждает
правомерность целевой должности. Миграция `0004_access` включает RLS на
`knowledge.spaces`, `knowledge.materials` и `knowledge.records`.

- Владелец видит личные объекты. Руководитель отдела видит отправленный ему
  на проверку объект. Остальное личное пространство в этот момент закрыто.
- Во время разбора руководитель назначенного отдела может читать личные
  материалы до `review_until`. Закрытое назначение само по себе доступа
  к личному пространству не даёт.
- Публикации доступны в пространстве текущей должности и области текущего
  отдела. При переводе внутри отдела публикации прежней должности по-прежнему
  доступны через отдел. Архивные публикации из выдачи исключены.
- HR и аудитор не получают доступ к содержимому. Административные запросы на
  выпуск приглашений используют отдельное подключение `estafeta_admin`
  без `SELECT` на таблицы пространств, материалов и записей.

`knowledge_transaction` устанавливает `app.user_id` локально для транзакции
по проверенной сессии. После завершения транзакции параметр не действует
в пуле. Доверенный сервер приложения устанавливает этот параметр, поэтому
доступ к паролю роли `estafeta_app` следует ограничить сервером.

Чтение материала или записи проходит RLS и `can_read`. Запись контента
под прикладной ролью закрыта до появления операций загрузки и публикации.
HTTP-маршруты работы со знаниями появятся на соответствующих этапах.

## Обновление базы с этапа 3

На новом томе PostgreSQL Compose создаёт роль автоматически. На существующем
томе добавьте `ESTAFETA_ADMIN_PASSWORD` в `.env` и создайте роль через
кластерного администратора. Например, запустите
`docker compose exec db psql -U postgres -d postgres`, затем выполните команды
ниже. Используйте значение `POSTGRES_DB`, если оно отличается от `estafeta`.

```sql
CREATE ROLE estafeta_admin LOGIN;
\password estafeta_admin
GRANT CONNECT ON DATABASE estafeta TO estafeta_admin;
```

Введите пароль из `ESTAFETA_ADMIN_PASSWORD` при запросе `psql`.
Затем запустите `docker compose up --build`. Для запуска вне Compose
задайте `DATABASE_ADMIN_URL` и примените `alembic upgrade head`.
