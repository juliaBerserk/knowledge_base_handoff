# Этап 11 — администрирование и сводка HR

После входа с TOTP администратор открывает «Администрирование». Для новой
организации сначала создайте отделы и должности в одноимённой вкладке.
Затем создайте учётную запись вручную или загрузите CSV.

Учётная запись сразу получает назначение и приглашение на 72 часа. Сотрудник
задаёт пароль самостоятельно. При подключённом SMTP и указанном адресе
система отправляет приглашение письмом. Для неотправленных писем и сотрудников
без корпоративной почты интерфейс показывает ссылки для личной передачи.
Ссылки выдаются в ответе на создание или перевыпуск. После ухода с экрана
можно выпустить новую ссылку из строки сотрудника в справочнике.
Повторная выдача аннулирует предыдущую ссылку, не меняя пароль сотрудника.

## Импорт CSV

Файл в UTF‑8, с BOM или без него, до 128 КиБ и 300 строк данных.
Разделитель — запятая или точка с запятой. Поддерживаются два набора заголовков:

```text
ФИО;корпоративная почта;отдел;должность;роль
full_name,corporate_email,department,position,role
```

Отделы и должности должны существовать в справочнике. Если название
неоднозначно, укажите его UUID. Почту можно оставить пустой. Роли задаются
как «Сотрудник», «Руководитель отдела», «HR», «Администратор», «Аудитор ИБ»
или как `employee`, `department_head`, `hr`, `admin`, `security_auditor`.

Проверка показывает номера строк с ошибками. При подтверждении файл
проверяется повторно. Учётные записи, назначения, хэши приглашений и аудит
создаются в одной транзакции. При конфликте отклоняется весь импорт.
Для учёток без почты дубликат определяется по совпадению ФИО и должности.
Отправка SMTP начинается после фиксации транзакции и ограничена по времени.

## Настройки и права

В админке доступны обязательность проверки публикаций и политика хранения
после 30 дней разбора. Значение из БД переопределяет `HANDOFF_RETENTION`.
Политика применяется к новым эстафетам.

Административное SQL-подключение читает только организационные данные и
состояния учёток. Проверка сессии и выпуск приглашения выполняются через
узкие функции БД. Роль администратора не получает `SELECT` на материалы,
записи, чанки, историю чатов, хэши паролей, токены сессий или приглашений.

В «Эстафеты → Сводка по эстафетам» HR видит счётчики увольнений и переводов
по статусам и число увольнений без назначенного преемника. Руководитель
видит сводку только своего отдела. Детали полноты отображаются счётчиками
по категориям.

## Запуск и API

Запустите `docker compose up --build` для применения `0011_administration`.
Новых подключений или секретов для миграции не требуется.

- `GET /api/admin/org`, `POST /api/admin/departments`, `POST /api/admin/positions`
  — организационный справочник.
- `GET /api/admin/accounts`, `POST /api/admin/accounts` — поиск и создание учёток.
- `POST /api/admin/accounts/import/preview`, `POST /api/admin/accounts/import`
  — проверка и атомарный импорт CSV. Текст передаётся в `csv_text`.
- `GET /api/admin/settings`, `POST /api/admin/settings` — настройки
  `review_required` и `handoff_retention`.
- `GET /api/handoffs/summary` — агрегированная сводка.

Для POST необходимы JSON, CSRF-токен и активная сессия.
